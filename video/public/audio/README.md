## Founder voice-over (replaces the HeyGen track)

When `voiceover-raw.wav` (the founder reading SCRIPT.md, all scenes in order) is here, `node scripts/fit-voice.mjs`
(or `bash scripts/finalize.sh`) rebuilds `voiceover.wav` and `voiceover.srt` from it: it cuts the take into the 65
cues, places each at its `captions.json` `startMs`, stretches overlong cues by at most 1.12x, and normalises to
-16 LUFS / -1.5 dBTP, 205.000 s, 48 kHz stereo. Before its first overwrite it copies the HeyGen partial to
`voiceover-heygen-partial.wav` / `.srt` (once; later runs never touch the backup). It also writes `ALIGN-REPORT.md`
(what went where, and what to fix) and `voiceover-align.json`. Fixes go in `cue-overrides.json`:

```jsonc
{
  "cues": { "S1-07": ["0:29.80", "0:32.45"], "S7-04": null },   // pin a cue to a range of the raw take, or leave it silent
  "ignore": [["1:07.50", "1:10.10"]]                             // coughs, false starts, retakes
}
```

or in a re-read scene saved as `voiceover-raw-S4.wav` (the old reading of that scene is then ignored automatically).
`node scripts/mix.mjs` then writes `mix.wav` (voice + `music.wav` ducked ~6 dB under speech and a further 6 dB across
S4, 1.5 s fade-in, 2 s fade-out, plus the demo's UI audio if `fit-demo` kept it), mastered to -14 LUFS / -1 dBTP;
the Remotion `Full` composition plays it automatically. Everything below is the HeyGen pipeline.

## Files

| File | What it is |
|---|---|
| `voiceover.wav` | Full narration track: 205.000 s (9,840,000 samples), 48 kHz stereo, 16-bit PCM. Each cue is placed at its `captions.json` `startMs`, including the S4 lines over the founder's recording, with silence in between. Two-pass `loudnorm` to **-16 LUFS integrated, -1.5 dBTP** (currently measures -16.0 LUFS, -4.5 dBTP). |
| `voiceover-heygen-partial.wav` / `.srt` | Byte-identical copies of the HeyGen partial `voiceover.wav` / `.srt` (2 Oct 2026). `fit-voice.mjs` keeps them as the backup and never overwrites them. |
| `mix.wav` | **Currently the HeyGen partial mix:** `voiceover.wav` (HeyGen, 9 of 65 cues) + `music.wav`, made by `node scripts/mix.mjs --demo none`; 205.000 s, 48 kHz stereo, -14.0 LUFS, -1.4 dBTP. The Remotion `Full` composition plays it automatically. `bash scripts/finalize.sh` replaces it once the founder's voice is in. |
| `voiceover.srt` | One subtitle per caption cue (all 65). A generated cue runs from its first spoken word to the later of the clip end and the cue end, and never past the next cue. A pending cue uses its `captions.json` window. |
| `vo/<scene>-<index>.wav` | One clip per cue, e.g. `vo/S1-03.wav`. 48 kHz mono 16-bit, with leading and trailing silence removed. |
| `vo/manifest.json` | One entry per cue, in `captions.json` order (fields below). |
| `vo/CHANGES.md` | Every cue that was fitted (pause tightening, time-stretch, speed) or shortened, and the list of cues not generated yet. Written by `build.py`. |
| `music.wav` | 205.000 s HeyGen catalog music bed, 48 kHz stereo, -20 LUFS. Source, licence and the loop edit are in `MUSIC.md`. |
| `VOICE.md` | The chosen HeyGen voice and why. |

### `vo/manifest.json` fields

| Field | Meaning |
|---|---|
| `scene`, `index`, `id` | e.g. `"S1"`, `3`, `"S1-03"` |
| `file` | `"vo/S1-03.wav"`, or `null` while the cue is pending |
| `startMs` | where the clip is placed on the video timeline (the cue's `startMs`) |
| `endMs`, `windowMs` | the cue's `endMs` from `captions.json`, and `endMs - startMs` |
| `durationMs`, `clipEndMs` | the clip's real length, and `startMs + durationMs` |
| `words` | `[{word, startMs, endMs}]`: HeyGen's own word timestamps, moved onto the video timeline. They are corrected for the trimmed lead-in, any tightened pauses and any time-stretch. They agree with the audio onsets to within about ±70 ms; S1-02's first word is about 0.18 s late because of a breath before it. |
| `text`, `spokenText` | the caption text, and what is actually said (they differ only for S1-07) |
| `status` | `ok`, `overrun` (longer than its window, never by more than 200 ms), or `pending` |
| `speed`, `fit` | the HeyGen speed used, and any post-processing applied |

## Fitting rule

A clip may not run past its cue window (`endMs - startMs`) by more than 200 ms. When a take is too long,
`build.py` fits it in this order:

1. Trim leading and trailing silence (always).
2. Shorten internal pauses of 160 ms or more to 120 ms, with 10 ms crossfades.
3. If it is still too long, apply a pitch-preserving `atempo` of at most 1.10x.

The proper fix is a regenerated take at a faster HeyGen `speed`. `speeds.json` already holds the speeds for the
four cues that needed fitting. One cue had to be shortened: **S1-07** drops "Worldwide," (see `vo/CHANGES.md`).
Today, S1-05 runs +2 ms over its window and S1-07 +186 ms; both are within the 200 ms rule.

## Re-running

The pipeline lives in `video/voiceover-pipeline/`, outside `public/`, so the raw takes don't get bundled.

```bash
cd video/voiceover-pipeline
npx hyperframes auth status   # needs HeyGen voice credit (OAuth free allowance or $HEYGEN_API_KEY)
node gen.mjs                  # generate every missing cue -> raw/<id>.mp3 + raw/<id>.words.json; stops on HTTP 402
node gen.mjs S1-01 S1-03 S1-05 S1-07   # replace the fitted takes with faster ones from speeds.json / text-overrides.json
python3 build.py              # -> vo/*.wav, vo/manifest.json, vo/CHANGES.md, voiceover.wav, voiceover.srt
./music.sh                    # -> music.wav (only needed if the music source changes)
```

- `gen.mjs` calls HeyGen `POST /v3/voices/speech` through the media-use skill's `synthesizeHeygen()` (from
  `.agents/skills/media-use/audio/scripts/lib/tts.mjs`). It uses voice Vincent (`f43e55ae9fb540c6b62e23081c951748`),
  speed 1.0 unless `speeds.json` says otherwise, and the `captions.json` text unless `text-overrides.json` says
  otherwise. It skips cues that already have a take.
- `build.py` reports every overrun and overlap on stdout. If a new take still overruns after fitting, add its id to
  `speeds.json` (for example 1.1), run `node gen.mjs <id>`, then run `build.py` again.
- `edits.json` holds editorial cuts made on an existing take (S1-07). Each edit applies only while the take's text
  matches its `appliesToText`.
- The raw HeyGen mp3s (44.1 kHz mono) are kept in `raw/`, and the three-voice S0 audition in `auditions/`.

Total speech so far: 26.7 s placed in 29.0 s of cue windows. At speed 1.0 these 9 takes came to 28.7 s against
29.0 s, but 4 of the 9 ran past their own windows. Expect a similar share of the remaining 56 cues to need a 1.05 to
1.15 speed. All 65 windows add up to 172.6 s.

## ffmpeg commands

Per clip (`build.py`). The threshold is -45 dB RMS because the HeyGen takes carry a -50 to -65 dB noise floor
before the first word, which a -50 dB peak gate would not trim:

```bash
ffmpeg -i raw/S1-03.mp3 -ac 1 -ar 48000 -c:a pcm_s16le full.wav
# leading trim only, to measure how much was removed (the word-timestamp offset)
ffmpeg -i full.wav -af "silenceremove=start_periods=1:start_threshold=-45dB:start_silence=0.02:detection=rms" lead.wav
# leading and trailing trim (trailing = reverse, trim, reverse)
ffmpeg -i full.wav -af "silenceremove=start_periods=1:start_threshold=-45dB:start_silence=0.02:detection=rms,\
areverse,silenceremove=start_periods=1:start_threshold=-45dB:start_silence=0.06:detection=rms,areverse" \
  -c:a pcm_s16le vo/S1-03.wav
# only when still over the window after pause tightening
ffmpeg -i vo/S1-03.wav -af atempo=1.0165 -ar 48000 -ac 1 -c:a pcm_s16le out.wav
```

Full track: the clips are summed into a 205 s 48 kHz buffer at their `startMs` (numpy), then normalised in two
passes:

```bash
ffmpeg -i pre.wav -af loudnorm=I=-16:TP=-1.5:LRA=11:print_format=json -f null -     # pass 1: measure
ffmpeg -i pre.wav -af "loudnorm=I=-16:TP=-1.5:LRA=11:measured_I=…:measured_TP=…:measured_LRA=…:\
measured_thresh=…:offset=…:linear=true,aresample=48000,apad,atrim=end_sample=9840000" \
  -ar 48000 -ac 2 -c:a pcm_s16le voiceover.wav                                       # pass 2: apply, pin to 205 s
```

Music: see `music.sh` (an `atrim`/`acrossfade` loop edit, `afade`, then the same two-pass `loudnorm` at `I=-20`).
