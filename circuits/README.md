# CargoFlow circuits: proof of physical state

A Groth16 circuit that proves, without revealing the readings, that **every temperature in a committed
telemetry epoch lay inside the policy range**. It is how a paused facility recovers with `resumeWithProof`.

```
statement:  there exist 8 hidden readings whose salted Poseidon Merkle root is `merkleRoot`
            and every reading's temperature is within [minTemp, maxTemp]

public:     contextHash, merkleRoot, minTemp, maxTemp
private:    per reading: timestamp, sensorField, temp, humidity, lat, lon, shock, salt
```

| | |
|---|---|
| Circuit | `telemetry_epoch.circom`, `TelemetryEpoch(3)` (8 leaves) |
| Constraints | 13,494 (2^14 powers of tau) |
| Proving key | `keys/telemetry_epoch_final.zkey`, 5.9 MB |
| Proof generation | about 2 s on a 16-core workstation, including Node start-up (measured) |
| On-chain cost | `resumeWithProof` with real verification: **247,611 gas** end to end (measured) |

## Why the proof cannot be reused elsewhere

The contract derives all four public signals from its own state; the caller supplies only the proof.

- `merkleRoot` is the root already committed in `EvidenceRegistry` for that exact epoch.
- `minTemp` / `maxTemp` are the shipment's policy bounds, offset-encoded (`temp x100 + 10000`).
- `contextHash = keccak256(chainId, verifier, controller, shipmentId, epochId, policyCommitment,
  submitter, pauseCount) mod p` binds the proof to one chain, verifier, controller, facility, epoch,
  policy, submitter and pause. A proof copied to another shipment, contract, chain or submitter, or
  reused in a later pause, fails verification.

Tests cover each case at the proof level (`test/proof.test.js`), at the contract level with a mock
verifier, and end to end with a **real proof and the real verifier**
(`contracts/test/integration/RealProof.t.sol`).

## Design notes and known limits

- **Deviation from the docs:** the docs sketch a Poseidon context computed inside the circuit. Here the
  context is a keccak hash reduced into the field, computed by the contract and passed as a public input,
  because that is cheap on-chain. The binding is equivalent for replay protection: the verification
  equation rejects any proof whose public inputs differ from the ones it was generated for.
- **Trusted setup is single-party and for testnet only.** No public powers-of-tau file was reachable, so
  phase 1 is generated locally in `scripts/setup.js`. The proof system is therefore only as trustworthy as
  the discarded entropy of one machine. A production deployment must use a public multi-party ceremony and
  a multi-contributor phase 2. Do not present these keys as secure.
- **A proof is not evidence that the sensor was honest.** It shows the committed readings satisfy the range.
  Sensor trust comes from credentials, reliability weighting and multi-sensor conflict detection.
- **Fixed size.** The circuit proves exactly 8 readings. Recovery epochs are built as their own 8-reading
  epochs (the backend's `ReadingsPerSensor = 8` with a single probe), not as slices of larger epochs.
- **Malformed proofs are expensive for the caller.** The snarkjs verifier forwards nearly all remaining gas
  to the pairing precompile, so an off-curve proof burns the gas forwarded. Only the exporter or a facility
  manager can call `resumeWithProof`, and only the caller pays. Well-formed but invalid proofs fail cheaply.
- **Licensing:** `contracts/generated/Groth16Verifier.sol` is GPL-3.0 (generated by snarkjs); see `NOTICE`.

## Cross-language contract

`lib/epoch.js`, `backend/internal/merkle` (Go) and the circuit must agree on the leaf encoding:
`leaf = Poseidon(timestamp, sensorField, temp+10000, humidity, lat+90e6, lon+180e6, shock, salt)`.
`test/fixtures/epoch_fixture.json` is generated by the Go backend from a real simulator run
(`go test ./internal/epoch -run TestCircuitParityFixture -update`); the JS reference and the circuit
must reproduce its leaves and root, and the Go test fails if the file drifts.
