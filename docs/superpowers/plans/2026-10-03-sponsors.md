## 1. ZeroDev: passkey smart accounts with sponsored gas
- Frontend: `@zerodev/sdk` + `@zerodev/passkey-validator`. "Continue with passkey" in the wallet modal creates a
  Kernel v3 account whose signer is a WebAuthn passkey (Face ID / fingerprint / Windows Hello).
- ZeroDev's hosted bundler does not list Robinhood testnet, so the Kernel client points at **Alchemy's bundler**
  and **Alchemy Gas Manager** as paymaster (ZeroDev's SDK accepts any ERC-4337 bundler and paymaster URL).
  Passkey registration uses ZeroDev's passkey server (project id).
- Flows: buyer `markDelivered`, exporter `resumeWithProof` / `startTransit`, arbiter actions; gas sponsored within
  a Gas Manager policy (per-address and daily caps). The wallet modal shows "Gas paid by CargoFlow".
- Backend: signed requests from Kernel accounts already verify through EIP-1271; add a test with a real Kernel
  passkey signature.
- Contracts: no custom account code; v3 tests confirm every role works when `msg.sender` is a contract account.

## 2. Alchemy: RPC and webhooks
- RPC order in backend and web app: QuickNode (primary) → Alchemy (fallback) → public RPC. `foundry.toml` gets an
  `alchemy` endpoint read from env.
- `POST /v1/webhooks/alchemy`: verifies `X-Alchemy-Signature` (HMAC-SHA256 of the raw body with the webhook
  signing key, constant-time compare), accepts Custom Webhook (GraphQL log filter) deliveries for the
  FinancingController, ReceivableVault, CoverPool and v3 contracts, and **wakes the indexer immediately** for the
  block. The payload is never trusted on its own: the indexer re-reads the logs from RPC, so a forged or replayed
  delivery cannot change state. Replays are rejected by delivery id. Result: dashboards update in about a second
  instead of on the poll interval.
- The webhook is created through Alchemy's Notify API by a script (`backend/cmd/alchemy-webhook`) so the address
  list and GraphQL filter stay in code.

## 3. OpenZeppelin
- Already used: `AccessControlDefaultAdminRules` (CargoFlowAccess, two-step admin transfer with delay),
  `SafeERC20` (vault, cover pool), `ReentrancyGuard` (controller, vault, cover pool), `ERC20` (MockUSDG),
  `ERC721` (v3 eBL), `Math`.
- v3 adds `Pausable` as an emergency brake on new risk only (new facilities, deposits, cover offers, title binding,
  device registration). Settlement, delivery, payouts, refunds and withdrawals are never pausable, so funds cannot
  be trapped.
- `docs/architecture.md` gets the contract → OpenZeppelin module matrix.

## 4. Dune Analytics
- Dune supports Robinhood Chain (`robinhood.*` tables, decoded tables `{project}_robinhood.{contract}_evt_*`).
  Testnet coverage is not documented; if testnet logs are not queryable, the backend pushes CargoFlow's indexed
  events to Dune through the **Dune upload API** (`dune.<team>.cargoflow_*` tables, refreshed every 15 minutes) and
  the queries run on those. Both forms of each query are kept.
- `analytics/dune/1_total_volume_and_tvl.sql`, `2_anomaly_and_pause_rate.sql`, `3_lending_waterfall_yield.sql`,
  plus a README; queries created through the Dune API; dashboard link in README and the site footer.

## 5. Fhenix: confidential invoice terms (Arbitrum Sepolia)
- Fhenix CoFHE runs on Ethereum Sepolia, Arbitrum Sepolia and Base Sepolia, not on Robinhood Chain. The library is
  Fhenix's `@fhenixprotocol/cofhe-contracts` (`FHE.sol`, `euint64`); `fhevm` is Zama's, a different product.
- `contracts/confidential/ConfidentialInvoiceTerms.sol` (separate Foundry project) deployed on Arbitrum Sepolia:
  the exporter stores the encrypted invoice margin and penalty schedule (penalty per excursion hour, cap) keyed by
  the CargoFlow shipment id; the contract computes the penalty from the public excursion count under encryption
  and only the exporter, financier and buyer can decrypt (cofhejs permits). The Robinhood facility stores nothing
  new; the link is the shipment id plus a commitment shown on the dashboard. No trustless bridge between the two
  chains: the dashboard reads both and says so.
- `docs/project/08-zk-and-privacy.md`: ZK proves facts about private readings; FHE computes on private commercial
  terms. They protect different data.

## 6. GMX: optional financier hedge (Arbitrum Sepolia)
- GMX v2 testnet runs on Arbitrum Sepolia and Avalanche Fuji, not on Robinhood Chain.
- Escrowed USDG is **not** moved into GMX: escrow must be available the moment evidence releases it, and a
  leveraged position can be liquidated, which would break the core guarantee. Yield on escrow is out.
- Instead, `contracts/hedge/GMXHedgeVault.sol` on Arbitrum Sepolia: a financier deposits their own collateral
  and opens or closes a GMX v2 position (through `ExchangeRouter.createOrder`) on a market they choose, sized to
  their CargoFlow exposure and tagged with the shipment id. The financier portal adds "Hedge price exposure via
  GMX" with live position, PnL and close. Pharma has no GMX market; the hedge fits commodity-linked cargo or FX
  exposure, and the UI says that.
