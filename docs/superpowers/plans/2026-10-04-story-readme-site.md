# Story-led README, docs and website (2026-10-04)

Requested by the founder: a complete, professional README and docs that explain every part of CargoFlow through the
video's cast and assets (no AI-looking images), and a website that introduces the same characters with GSAP motion so
non-specialists understand it. Code is shown in light themes, not dark.

## Shared visual source

All illustration comes from the Remotion library already in `video/src` (characters, assets, maps, scenes): the
same flat system, brand palette (paper/white, navy ink, lime #C6F432, emerald, amber, red only for excursions).
Nothing generated by image models.

## 1. Media kit (`docs/assets/v3/`)

Rendered from Remotion with new, purpose-built compositions in `video/src/readme/`:
- `banner.png` (1600x560): CargoFlow wordmark, the line "Working capital that releases only when the cargo's own
  evidence says it should", the cast and the reefer on the route line.
- `cast.png`: Meera (exporter), Daniel (financier), Wei Lin (buyer), Arbiter, Insurer, Carrier with one-line roles.
- One short looping GIF per concept (720 px wide, 12 fps, under 3 MB each): the problem (paperwork, not the
  container), facility and milestones on the map, signed readings becoming an evidence epoch and score, release and
  place hold, excursion and pause, zero-knowledge recovery with the "proof ready" notification, settlement waterfall,
  bill of lading under documents against payment, default and parametric cover, passkey sign-in, Claude via MCP.
- `architecture.png`: the system diagram redrawn in the new theme (web app, Go service, contracts, sensors, Claude/MCP,
  sponsors), with the characters at their entry points.
- `sponsors.png`: the partner track with what each one does.
- Light-theme terminal and code captures (freeze, light theme): the testnet lifecycle run, `forge test`, `go test`,
  vitest and Playwright summaries, a signed telemetry request, the MCP config.
- Real product captures: redesigned website pages and the claude.ai screens from `video/public/footage/claude`.

## 2. README and docs

The README tells the story in the video's order with images in every section: banner, the problem with the real
sources, the cast, how it works (one GIF per step), the live product (screenshots with links), Claude and the MCP,
architecture, live deployments (every contract with explorer links, the live v3 runs with transaction links),
sponsor integrations, developer platform, measured numbers, honest limits, video. `docs/` gets a guide per role
(exporter, financier, buyer, carrier, arbiter) with the same characters, and the docs index links everything.

## 3. Website

- A `Cast` component set in `frontend/src/components/cast/` ported from the video's SVG rig (static poses and
  expressions, light idle motion with CSS/GSAP, no Remotion dependency).
- Landing: "Meet the people" with the six characters and their roles, the how-it-works story told by the characters
  with GSAP ScrollTrigger (pinned steps, the route line drawing, the reefer warming, the proof unlocking the vault),
  and sliding carousels for roles and testimonials-style use cases.
- Portals greet each role with its character; empty states use the cast.
- Code blocks switch to a light theme across the site (developers, docs, gateway snippets).
- Motion respects `prefers-reduced-motion`; performance budget LCP under 2.5 s, CLS under 0.05; all e2e labels kept.

## Order

Media kit and website run in parallel. README and docs follow the media kit; site screenshots in the README are
refreshed after the website deploy. The final video render (passkey payment shot, 277 tests) runs alongside.
